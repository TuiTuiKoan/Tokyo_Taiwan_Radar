04
03 ・ F — Three Modalities

F1 Stable & Auditable · F2 Flexible Judgment · F3 Discerning Structure

F1

Stable · Auditable

  • Processing repetitive/complex tasks
  • Traditional automation
  • High compliance requirements, high precision data

→ Often doesn't need an agent

F2

Adaptability

  • High cost
  • Flexible judgment required
  • No standard answer

→ Where agents truly shine

F3

Discerning Structure

  • Step 1: Determine if it's F1 or F2
  • F1 → Deterministic Rules / Code
  • F2 → Implement Agents
F1, F2, and F3 require very different approaches — understand how "Function" translates, then think about "Structure."

04 ・ S-4c

How Normative Design Manifests Across Three Layers

Ⅰ

Code Layer ・ Event dataclass

Standardized fields: source_id (stable), start_date (no fallback), multi-language name_ja/zh/en, three-part location (location_name/address/prefectures).
📎 base.py#L120–165

Ⅱ

Skill Layer ・ Taiwan Relevance Rules

The "Wansei" signal, concrete selection reason format, three-stage filter order (title → venue → keyword).
📎 SKILL.md#L15–31

Ⅲ

Agent Layer ・ Read rules before acting

Agent Session Start Checklist: read SKILL.md before implementing. Next time you fix a bug, crystallize the lesson back into Skill.
📎 agent.md#L20–24

Core principle: Code solidifies, Skills evolve, Agents execute—three layers iterate to drive "auditable norms."

Re-evaluating Design Variables

R: Req, F: Func, Be: Exp. Behavior, Bs: Str. Behavior, S: Struct, D: Design Desc.
Single arrow＝Transformation, Double arrow＝Comparison.

  • How the site works ─ F
  • How the site is built ─ S
  • Relationship between Design and Build ─ B
Everything is Probabilistic Control.
Goal: "Narrow the probability of failure," eventually "hardcoding" it into norms.
FBS Principle

Generating "Structure S" directly from "Req R" using LLMs often fails — it violates the FBS principle that Function cannot directly link to Structure without Behavior.

CASE STUDY19
06 ・ Independence and Commonality

Source Independence vs. Commonality

Independence

One Source, One Skill-History

  • Each data source corresponds to an independent agent / skill
  • Optimizing for source-specific quirks
Commonality

Cross-Agent Shared Skills

  • Shared logic (Taxonomy, Geocoding)
  • One fix benefits all sources
  • Driving architectural evolution
