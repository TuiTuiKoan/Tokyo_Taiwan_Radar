# Annotator Golden Set Evaluation

This directory stores per-run annotator accuracy reports generated by `scraper/eval_annotator.py`.

## File Naming

- `YYYY-MM-01-monthly.md` — Auto-generated monthly baseline (committed by CI)
- `YYYY-MM-DD-baseline.md` — Manual baseline runs

## Interpreting Reports

### Tier 1 (FC-backed)
Fields where a human explicitly corrected the AI's output via `field_corrections` table.
These are high-confidence ground truth entries. Tier 1 accuracy is the most reliable signal.

### Tier 2 (reviewed + spot check)
Fields from `annotation_status='reviewed'` events that were manually confirmed during
`build_golden_dataset.py --interactive` spot check. Medium confidence.

### Field comparison methods
| Field type | Method |
|---|---|
| `category`, `event_form` | Set equality |
| `is_paid`, `has_japanese_support`, `has_english_support` | Boolean equality |
| String fields | Exact match (strip whitespace) |

## Usage

```bash
# Run eval with frozen corrections (CI default — reproducible)
cd scraper
python eval_annotator.py --output report.md

# Debug with 5 cases
python eval_annotator.py --sample 5 --output /tmp/test.md

# Run a single case by ID
python eval_annotator.py --case a1b2c3d4 --output /tmp/test.md

# Run with live DB corrections (local dev, non-reproducible)
python eval_annotator.py --live --output report.md
```

## Building / Refreshing the Golden Set

```bash
# Interactive spot check (Tier 1 + Tier 2)
cd scraper
python build_golden_dataset.py --target 50 --interactive

# Refresh frozen_corrections.json only (after new corrections added to DB)
python build_golden_dataset.py --rebuild-frozen-only
```

## CI Trigger

The eval workflow (`.github/workflows/eval-annotator.yml`) triggers on PRs that modify:
- `scraper/annotator.py`
- `scraper/category_feedback.py`
- `scraper/selection_reason_feedback.py`
- `scraper/tests/golden/**`
- `scraper/eval_annotator.py`

Results are posted as a sticky PR comment.
