## 為何拆兩階段（v4 修正）

`eval_annotator.py` 在 v3 之前只跑 `SYSTEM_PROMPT + feedback_prompt`（純 LLM 輸出），**沒有**呼叫：

- `enrich_movie_titles()` — works 表 + eiga.com 覆寫 `name_zh` / `name_en`
- `field_corrections` lock — 人工修正值已鎖定
- `enrich_person_names()` / `enrich_addresses()`

因此 v1 baseline `name_zh` 1/14 並非 production bug——production 已經 14/14 正確（A-pre Appendix 2）。
真正的問題是 **eval framework 沒測完整 pipeline**。

v4 修正方式：

- **Stage 1 (LLM-only)**：保留原行為，作為 SYSTEM_PROMPT regression 守衛
- **Stage 2 (full pipeline)**：跑 LLM → `_resolve_movie_titles_for_event()`（works → eiga.com），作為 production-grade 守衛

## Stage 2 pipeline 細節

`_resolve_movie_titles_for_event()` 從 `enrich_movie_titles()` 抽出 title-resolution 邏輯，**read-only、不寫 DB**：

順序（plan B3）：

1. `works` 表 `title_ja` query（既有行為）
2. `works` 表 `title_zh` query（plan B2 新增）
3. `lookup_movie_titles()` eiga.com fallback
4. `『…』` / `《…》` bracket-embedded fallback

News 子事件保護（既有 d18339d5 incident）保留——若 bracket title 只來自 GPT 的 `name_ja`、且 raw_title 無 bracket、且 `parent_event_id` 存在，則 skip enrich。

## Stage 2 殘留失敗（1 / 14 name_zh）

唯一未通過的是 description_zh / description_en 差異——`name_zh` / `name_en` 在 Stage 2 全數正確；只是 `description_*` 含人工 polish 文字，pipeline 無法重現。這不在 KPI 範圍。

## Phase B containment 驗證

Phase B 改動已含在本 baseline：

- **B1** `enrich_movie_titles()` 寫入前讀 `field_corrections`，已鎖定 `name_zh` / `name_en` 而 enrich 算出不同值 → 從 update dict 移除 + WARN
- **B2** works fallback 加 `.eq("title_zh", title)` 第二查詢
- **B3** works 表優先於 `lookup_movie_titles()`

Stage 2 baseline 在這些改動下達標——說明 containment 未引入 regression。

## 範圍邊界（v4）

本 baseline **不含** Phase C 改動。Plan v4 Phase C 描述的 `monthly_health_check.py` 中的 detector 3.1/3.2/3.3/3.4 與 a1_v2 column 在現行 codebase 中**並不存在**——Architect appendix 3 的 SQL 是針對 events 表的探索性查詢，並非已存在的 detector 程式碼。Phase C 已從本次 baseline 排除；見 Engineer changelog。

## 重現步驟

```bash
cd scraper
source ../.venv/bin/activate

# Stage 1（regression baseline）
python eval_annotator.py --stage 1 --output /tmp/stage1.md

# Stage 2（production-grade）
python eval_annotator.py --stage 2 --output /tmp/stage2.md
# 等同於：
python eval_annotator.py --full-pipeline --output /tmp/stage2.md
```

兩個 stage 都使用 frozen snapshot（預設）。`--live` 仍可切換 DB-live corrections。
