# Tokyo Taiwan Radar 2.0：Pivot 定位與需求規劃

> 本文件合併兩份外部研究（報告 A、報告 B），比較兩者的優缺點，整理成 TTR 下一階段網站 pivot 的**需求規劃基準**。
> 它不是實作 spec。之後每個功能都應拆成 `docs/specs/active/<slug>/`，並在 References 引用本文件。

---

## 0. 一頁摘要

**一句話策略（北極星）**

> **Tokyo Taiwan Radar ＝ 把日本人的「台湾好き」，變成行動與人際關係的服務。**
> interest → participation → relationship

**現階段切入點（Wedge）**

> **在日本與台灣相遇的行事曆**：用 AI 標註，做出跨平台、三語、可依「興趣領域 × 交流強度」篩選的台灣相關活動索引。

兩句話的關係：北極星（出自報告 B）決定產品往哪裡長；切入點（出自報告 A）決定先用哪一塊既有資產贏下第一批用戶。活動索引是入口，「人、場所、社群」是護城河。

**五個關鍵決策**

1. **從資料中心轉為人中心**：首頁不再由「資料庫裡有什麼」決定，改由「這位使用者現在想往台灣靠近哪一步」決定。全部活動列表移到「レーダーを見る」。
2. **先修精準度，再加來源**：現況是 high recall／low precision，非台灣或泛政治內容混進 feed。Taiwan relevance scoring 列為 P0，暫停無差別擴充爬蟲。
3. **標籤從「內容分類」擴充到「行動門檻」**：在既有類別之外，新增交流強度、語言可及性、入門友善度與社交可負擔性（一人OK、日本語だけでもOK等）。
4. **從單一 Event 擴充為四種實體**：Event／Person（創作者、主辦者）／Community／Place，逐步建立 Taiwan interest graph。
5. **不自建聊天、論壇、訂票、餐廳評分**：TTR 是 LINE、Meetup、Peatix、Instagram 之間的「導航與轉接層」，不取代它們。

### 1.1 各自特色與優缺點

| 面向 | 報告 A（Claude 深度研究） | 報告 B（OpenAI 分析） |

### 1.2 共識（直接採用）

- 日本目前沒有服務統合台灣相關的旅遊、語言、文化、同好與活動資訊。TTR 的跨來源發掘能力是最難複製的資產。
- 不正面對抗 HelloTalk／Tandem（語言配對）、KKday／Klook（旅遊商品）、食べログ（餐廳評分）、LINE／Instagram（社群互動）。
- 不自建聊天室或論壇，改做社群 directory 與導流。
- 創作者、研究者與小型主辦者是生態的**節點**，不是廣告客戶。主辦者投稿與主辦者頁是供給飛輪。
- 不做「台灣人經營認證」或政治立場標籤；去政治化、透明來源與 moderation 是信任基礎。
- 首頁要降低參與的心理門檻：「中文不會也 OK」「一人參加 OK」這類資訊比「音樂／電影」更能促成行動。
- 品牌保留 Tokyo Taiwan Radar，用副標說明全日本範圍；Tokyo 是品牌的出生地，不是地理限制。
- 不以政府機關與企業為服務對象（政府活動只作資料來源）。

### 1.5 與既有策略文件的衝突（需創辦人決定）

`docs/specs/active/market-positioning-strategy/proposal.md`（2026-05）的三層火箭定位是：

- 表層 B2C 免費入口 → **中層 B2G／B2B 數據服務（主要變現引擎）** → 深層 B2B 市場媒合。
- 該文件認為「在日台人 B2C TAM 太小，不能直接變現」。

兩份新報告都**排除政府與企業作為服務對象**，並把重心放在 B2C 的日本人用戶。這和三層火箭的「中層為主要變現引擎」方向不同。

> **待決定 D1**：TTR 2.0 是否正式取代三層火箭？
> - 選項 1：2.0 取代舊定位，B2G／B2B 停止規劃。
> - 選項 2：2.0 是「表層」的重新設計，中層與深層暫緩但保留。
> - 選項 3：維持三層火箭，2.0 只採用首頁與標籤改版。
>
> 本文件預設**選項 2**：B2C 的人際入口是信任與資料累積的來源；新的 Person／Community 實體也會強化未來任何資料服務。但「不以政府、企業為對象」的限制必須明確寫回舊 spec。

另一個注意點：新族群是**日本人**，舊文件路線 1 的族群是**在日台灣人**。2.0 中在日台灣人轉為「供給方與交流對象」（P3 persona）。

## 2. 市場：五種需求是一條連續的成長路徑

採用報告 B 的框架，並補上報告 A 的競品判斷。

| 階段 | 使用者心態 | 真正要解決的問題 | 現在去哪裡 | TTR 2.0 的角色 |
|---|---|---|---|---|
| ① 台湾が気になる | 第一次或再次去台灣 | 去哪、花多少、怎麼不只當觀光客 | Google、IG、YouTube、KKday、地球の歩き方 | **輕做**：「行前在日本先遇見台灣」策展 |
| ② 台湾の人と話したい | 學台灣華語 | 實際開口、問台灣人、交朋友 | HelloTalk、Tandem、LINE OpenChat、Meetup | **次要**：交流場合聚合＋程度與門檻標籤 |
| ③ 台湾の○○が好き | 音樂、電影、原住民、文學、茶等 | 還能去哪裡深入、誰跟我一樣喜歡 | X、IG、Peatix、個別帳號 | **主戰場**：次領域頻道、追蹤、通知 |
| ④ 台湾好きの仲間がいる | 已形成興趣圈 | 哪些店、活動、人值得信任 | LINE OpenChat、FB、Discord | **導流**：社群 directory、策展 collection |
| ⑤ 自分も発信する | 自己成為主辦者或創作者 | 讓真正喜歡這個領域的人發現我 | IG、YouTube、X、Peatix | **供給飛輪**：投稿、主辦者／創作者頁 |

**市場規模訊號**（詳細出處見 §12）

- 2025 年訪台日本旅客 1,483,176 人次（+12.4%），是台灣最大客源市場；重遊率 49%，20 多歲佔 19%。
- 2025 年底在留台灣人 73,256 人，創歷史新高，是交流活動台灣側的供給基礎。
- 日本人對台灣有親近感 74.5%。
- 交流需求有實際證據：Meetup「Tokyo Chinese & Taiwanese Exchange」約 3,835 名會員、累計 661 場；「ゆる〜くお茶べり日台交流会」約 1,085 名會員，幾乎每週舉辦；LINE OpenChat「台湾好きが集まる部屋」約 1,600 人，成員從「準備第一次去台灣」到「去過 30 次以上」都有。

**結論**：市場的問題不是「要不要做台日交流」，而是「台日交流已經存在，但散落在數百個帳號、群組、活動與店家之間」。TTR 要做的是 navigation layer。

**長期威脅（報告 B 的關鍵提醒）**：在 AI 搜尋時代，「找活動」本身不是護城河，Google 與 AI 助理會越來越能直接回答。真正難以複製的是「哪些台灣人、場所、社群與活動彼此相關」的關係圖譜，以及經過人工校正的結構化標註。

## 4. 現況盤點

### 4.1 已有資產

- **來源與範圍**：163 個以上來源（2026 年 5 月），範圍全日本；首頁文案寫「47都道府県・100+のソース」，**需更新為實際數字**。
- **AI 管線**：電影海報視覺辨識、阻擋捏造主辦單位、簡轉繁校正、每日翻譯品質測驗、70 條以上永久防護規則、autoQA（8 月時剩 170 件以上待處理）、ground truth 評測。
- **資料模型**：`events`、`works`（同作品跨場館與巡演 1:N，已完成）。40 個 `Category`（`web/lib/types.ts`），含 `movie`、`indigenous`、`taiwan_mandarin`、`tea_alcohol`、`taiwan_japan` 等，以及 `CATEGORY_GROUPS`。
- **用戶功能**：三語、搜尋與篩選、長期活動、FAQ 結構化活動頁（利於 SEO／AEO）、一鍵加入行事曆、LINE 週報、`/saved` 收藏頁、`/account/events/new` 主辦者投稿（重建中）。
- **社群訊號**：早稻田大學日台留學生會、東京台灣之會曾主動接洽。

> 報告 B 說 TTR「缺乏收藏」，這不正確，`/saved` 已存在。真正缺的是 **follow（追蹤主題或人）** 和 **依追蹤內容的通知**。

### 4.2 核心問題

| # | 問題 | 來源 | 影響 |
|---|---|---|---|
| Q1 | **資料中心而非人中心**：首頁即 database view | B | 新用戶不知道從哪裡開始 |

## 5. 定位

### 5.1 北極星與切入點

- **北極星**：日本人の「台湾好き」を、行動と人間関係に変える。
- **不是**：台灣資訊媒體、純活動行事曆、旅遊指南、語言交換 App、餐廳評分網站。
- **切入點**：已入坑者每週都需要的「我的領域這週有什麼台灣活動」，加上讓人更敢參加的門檻標籤。

### 5.2 目標族群

## 6. 產品需求

需求編號格式為 `R-<區塊>-<序號>`，優先序見 §7。

### 6.1 精準度工程（P0）

| ID | 需求 | 驗收標準 |
|---|---|---|
| R-QA-1 | 每筆活動計算 **Taiwan relevance score**（0–1），依據包含：主辦者是否台灣相關、標題／內文中台灣元素的位置與比例、來源類型、是否只是附帶提及 | 已建立 ground truth 抽樣集；score 門檻能把首頁雜訊率降到 ≤ 5% |
| R-QA-2 | 分層顯示：高分進首頁與推薦；中分只在「レーダーを見る」與搜尋中出現；低分進人工佇列 | 首頁不出現 score 低於門檻的活動 |
| R-QA-3 | 內容類型分流：活動、文章或新聞、學術公告、商業新聞不再混在同一個 feed | 首頁只顯示「可以參加的活動」；其他類型有獨立入口或不顯示 |
| R-QA-4 | 政治與時事類（如 `geopolitics`）預設不進一般首頁推薦，只在使用者主動 follow 或搜尋時出現 | 編輯方針公開說明 |
| R-QA-5 | 暫停「無差別擴充爬蟲」。新來源必須先估計 precision | Researcher 的來源評估加入 precision 欄位 |

### 6.2 實體模型（P0–P2 分階段）

```
Event ──hosted_by──> Person/Organizer ──belongs_to──> Community
  │                       │
  ├──held_at──> Place <───┘ (常駐、經營)
  └──part_of──> Work（已存在）
所有實體 ──tagged──> Topic（次領域）
```

| ID | 實體 | 階段 | 說明 |
|---|---|---|---|
| R-EN-1 | Event | 既有 | 擴充 §6.3 的標籤欄位 |
| R-EN-2 | Person／Organizer | P0 | 創作者、樂團、研究者、主辦團體。頁面聚合 IG／YouTube／X 連結、相關活動、下一場活動、相關次領域。**不重新上傳作品**。 |
| R-EN-3 | Topic | P0 | 次領域頻道（音樂、電影、原住民與多元族群、語言、茶與食、文學與出版、學術、親子等），可 follow |
| R-EN-4 | Community | P1 | LINE OpenChat、Discord、Meetup 群組、學會。欄位：平台、語言、人數（快照日期）、社群規則（例如禁政治話題）、加入方式、相關 Topic |
| R-EN-5 | Place | P2 | 只收與活動或社群有關的場所（茶館、書店、常辦台灣活動的店、Live house）。**不收評分，不貼國籍或政治標籤** |

目標路徑：event → person → topic → community → next event。

### 6.3 標籤 schema（P1，Claude API 標註）

| 維度 | 值 | 來源 |
|---|---|---|
| 交流強度 | 観る（被動）／学ぶ（半互動）／話す（高互動） | A |
| 語言可及性 | 日本語だけでもOK／中国語初心者OK／華語中級以上／英語OK | A＋B |
| 入門友善度 | 初参加歓迎／已入門者向 | A＋B |
| 社交可負擔性 | 一人で行きやすい／台湾人と話せる／見るだけでもOK／途中参加OK | B |
| 費用 | 無料／¥1,000以下／¥1,000–3,000／¥3,000以上 | B（以既有費用欄位計算） |
| 主辦方類型 | 個人創作者／學術／社群／商業祭典／政府 | A |
| 台灣連結 | 台湾人主催／台湾から来日／台灣作品（電影、書、音樂） | B |
| 族群 | 親子OK／20代多め／年齢問わず | A＋B |
| 次領域 | 多標籤（可對應既有 40 個 `Category`） | A |

品質規則：

- 每個標籤附信心分數，低信心時不顯示，並送進人工佇列。
- 沿用「不捏造主辦方」規則：社交類標籤（一人OK、台湾人と話せる）**必須有原文依據**，沒有就留空，不推測。
- 先人工標註 200 筆 ground truth；precision ≥ 90% 才開放該篩選器。
- 每週抽檢 precision 與 recall。

### 6.7 社群 directory（P1）

- 整理並連結優質的 OpenChat、Discord、Meetup 與學會，**以導流取代自建論壇**。
- 每個社群必須標示：平台、語言、人數與快照日期、社群規則、相關 Topic。
- 收錄前要確認社群公開招募成員。私密社群不收錄。

### 6.8 Collection 與 Place（P2）

- Collection 是策展清單，例如「東京で台湾茶を飲むなら」「中国語初心者でも行きやすい交流会」。
- **必須署名策展人、寫明標準與資料來源**。帶價值立場的清單（例如「台湾人店主のお店」）只能以個人或社群名義發表，不能作為 TTR 官方認證。
- 初期只開放 TTR 編輯與邀請的策展人，P3 才考慮開放 UGC。
- 不做星等與評論。

### 6.9 旅遊（P1 輕做，P3 探索）

- **P1**：「台湾に行く前に」策展頁，用現有活動資料重組（祭典、入門講座、交流會、免費上映會），不寫預算或景點內容。
- **P3 探索**：「台湾に入る旅」：依預算 × 天數 × 興趣 × 交流，推薦台灣當地的小型活動、書店、語言交換。前提是取得台灣側的資料來源與夥伴，並由創辦人決定是否擴大範圍（見 §11 D3）。

### 6.10 語言（P1，P3 實驗）

- **P1**：語言交換與交流活動彙整，加上 §6.3 的語言與門檻標籤；在語言頻道區分台灣華語、台語、客語。
- **P3 實驗**：招牌、菜單看圖解讀（Claude 視覺），結果只導向既有語言社群。不做配對或聊天。

### 6.11 信任與編輯方針（P0）

- 公開「AI 標註說明」：哪些欄位是 AI 產生、怎麼校正、怎麼回報錯誤。
- 公開「編輯方針」：以文化、語言、藝術、生活為主，不做政治評論，不做國籍或政治立場認證標籤。
- 活動頁提供錯誤回報（日期、地點、主辦者錯誤），並排入人工佇列。
- 遵守各平台的 robots.txt 與使用條款；TTR 定位為上層索引，報名一律導回原始頁面。

## 9. 路線圖

### Phase 0（0–2 週）：清理與決策

- 創辦人決定 §11 的 D1–D3。
- 修正首頁數字（R-HP-5）。
- 盤點目前首頁雜訊樣本，建立 relevance ground truth 第一版（200 筆）。

### Phase 1（2–6 週）：驗證定位

1. **用戶訪談 8–10 人**（運用民族誌專長）：美咲型、健太型各 3–4 人，供給方 3 人。驗證 H1–H3（§11）。
2. **首頁原型 A/B**：「三選一」vs.「四意圖」，量測首次點擊率與 LINE 訂閱轉換。
3. **Relevance scoring 上線**（R-QA-1〜3）。
4. **標籤 schema 試標**：交流強度、語言可及性、入門友善度先做；precision ≥ 90% 才開放篩選。

### Phase 2（1–3 個月）：供給飛輪與留存

5. 投稿上線（R-SP-1〜2），邀請 10 個種子供給方：早大日台留學生會、東京台灣之會、日本台灣學會定例研究會（公開場次）、台灣獨立音樂巡演主辦、台灣茶教室、在日創作者等。
6. Person／Organizer 頁、follow Topic。
7. LINE 分眾通知（先開 4 個頻道）。
8. Community directory 第一版（20–30 個社群）。

### Phase 3（3–6 個月）：擴散與關係圖譜

9. 社群策略：X 每週人工發布 1–2 則精選圖卡（避免大量 API 自動貼連結）；Instagram 以海報輪播為主並標註主辦者。
10. follow Person、活動頁「參加後」區塊。
11. Place 與 Collection 小規模試行（邀請策展人）。
12. 品牌文案定案與 meta 更新。

| **S 優勢** | ① 跨平台聚合規模（163 個以上來源、全日本）與中日英三語，主題密度高於 Google 與 Peatix；② AI 管線具海報辨識、主辦方驗證、翻譯品質測驗、autoQA 與 ground truth 基礎；③ FAQ 結構化頁利於 SEO／AEO（Google、Claude、ChatGPT 爬蟲頻繁造訪）；④ 已有 `works`、收藏、投稿等基礎模組；⑤ 創辦人兼具 UX、設計民族誌與在日台灣人身分，易取得社群信任；⑥ 已有學生會與灣生團體主動接洽 |
| **W 劣勢** | ① 首頁資訊密度過高、資料中心而非人中心；② precision 不足，活動、文章、學術、商業新聞與政治內容混在同一 feed；③ 只有 Event 實體，缺 follow 與人、場所、社群的關係；④ AI 幻覺與欄位污染尚未根除（autoQA 仍有 170 件以上）；⑤ 個人專案，精力有限；⑥ 品牌認知低；⑦ 「Tokyo」品牌與「全國」範圍落差 |
| **O 機會** | ① 赴台日本人回升（2025 年 148 萬，+12.4%），20 多歲佔 19%；② 次文化活動供給旺盛（台灣文化中心 10 場上映會、獨立樂團巡演、多個大型祭典）；③ 日台交流社群已有千人級會員，但分散；④ 小型創作者與學會缺乏曝光管道，可成為供給飛輪；⑤ LINE、Instagram、YouTube 已成熟，TTR 只需做導航層；⑥ AEO 興起，結構化資料更容易被 AI 引用；⑦ 目前沒有平台統合「旅行 → 語言 → 文化 → 同好 → 活動」 |
| **T 威脅** | ① **AI 搜尋讓「找活動」商品化**，若 TTR 只是 aggregator，差異會越來越小；② 中日緊張與台海議題升溫，平台可能被貼上政治標籤；③ Instagram／X 掌握創作者關係，LINE 掌握社群黏著，HelloTalk／Tandem 有 network effect；④ X API 改為按量計費，帶網址貼文每則 0.20 美元；⑤ 來源網站改版、著作權與轉載爭議；⑥ AI 錯誤資訊（日期、地點）快速傷害信任；⑦ Peatix 等平台若強化分類與推薦，可能部分取代 TTR |

**交叉策略**

- **SO**：以三語 AI 標註＋主辦者投稿，搶佔「台灣次領域活動」與「台灣人與社群」的索引位置；用結構化資料拿下 AEO 流量。
- **WO**：relevance scoring 先解決 precision；用投稿取代部分爬蟲，降低維護負擔；用 follow＋LINE 分眾作為最小可行的留存。
- **ST**：把護城河從「找活動」升級為「Person／Community／Place 關係圖譜＋人工校正標註」，抵禦 AI 商品化；公開去政治化編輯方針、錯誤回報與人工審核。
- **WT**：控制範圍，不做餐廳資料庫、旅遊商品與聊天室，精力集中在一個切入 persona。

## 14. Caveats 與數據出處差異

- **數據不一致**：
  - LINE 月活：報告 A 引 LINEヤフー官方「破 1 億」，報告 B 引 DataReportal「約 9,900 萬」。定義不同，對外引用時以官方數字為準並註明定義。
  - Instagram／X：報告 A 用「利用率」與官方 MAU，報告 B 用「廣告觸及人數」（IG 6,320 萬、X 7,120 萬、YouTube 7,850 萬）。兩者不可直接比較。
  - 來源數：報告 A 為 163 個以上（2026 年 5 月），網站首頁寫 100+。以資料庫實際數字為準。
- **報告 B 的事實修正**：TTR 已有 `/saved` 收藏頁，缺的是 follow 與分眾通知。
- **報告 B 的雜訊範例**（中國近現代史、保險研究、非台灣藝人巡演等）來自某一時點的首頁快照，Phase 0 需以資料庫實際抽樣確認比例。
- TTR 的流量、用戶組成與留存率沒有公開數據，兩份報告的競爭判斷都以公開功能為準。
- 「日本台灣華語學習者增加」主要來自教師撰文與 TOCFL 國籍比例，應視為趨勢訊號。
- 「日本台灣料理店多由非台灣人經營」的說法全部來自部落格與 Q&A，沒有可信統計，只用來說明這類標籤的敏感性。
- LINE OpenChat、Meetup 人數、TIFE 社群規模、HelloTalk／Tandem 會員數為搜尋當下快照或業者自述，可能已有變動。
- 匯率與旅遊成本來自旅遊媒體估算，非官方統計。
- X API 價格以 @XDevelopers 2026-04-16 官方公告為準，實作前請以 X Developer Portal 再確認。
